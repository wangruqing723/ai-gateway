## 1. 目标

为可信本机管理页面提供可携带真实凭据的提供商／路由迁移包，以及经过脱敏预览、明确确认和版本裁决的导入。默认合并，另提供有破坏性提示的整体替换；不把配置片段直接交给全量 PUT，也不将普通查询改成明文。

范围是 `providers` 和 `routes` 两个持久化集合。路由的 `vision` 是路由自身字段，纳入迁移；全局配置、OAuth 账户令牌和运行状态不纳入。配置名称、匹配模式、提供商依赖和账户引用可以作为选择身份出现，其他配置原值不进入预览。

## 3. Module、Interface 与 Seam

### 3.1 专用迁移 Module

将迁移规则放在 `internal/config/transfer.go`，不新建通用迁移框架，不建立只有一个 Adapter 的抽象接口。迁移 Module 与配置校验处于同包，能复用默认值、限制常量、形状校验与引用校验，不复制一套规则。

外部 Interface 收敛为两项能力，名称可按现有 Go 命名细节调整，职责不变：

| 能力 | 输入 | 返回 | 不变量 |
|---|---|---|---|
| 导出迁移包 | 已保存配置快照、全部／选择信息 | 附件字节和无敏感值的元信息，或安全错误 | 不修改源快照、不读文件、不访问网络；隐含依赖在内部补齐。 |
| 规划导入 | 当前配置快照、源文档、导入选项、目标已有账户 ID 集合 | 安全目录／变更预览、阻止项及可应用的完整配置计划 | 不保存、不热重载、不返回明文配置给前端；缺少目标依赖时返回可修正的阻止项。 |

Implementation 内部承担严格解析、文件分类、选择裁决、依赖闭包、冲突、排序、OAuth 映射、差异、大小校验及完整配置构造。删除该 Module 后，这些复杂性会重新散落在 HTTP 和前端，因而它应提供真正的 Depth、Leverage 与 Locality。

实施拆分：`transfer_shape.go` 只负责严格 YAML 类型与别名图校验；保持现有 YAML 锚点／合并键兼容，限制 100 层嵌套和 65536 次节点检查，并缓存重复节点的检查结果，不建立新的外部 Interface。`transfer.go` 仍收口导出与规划。新增 HTTP smoke 放在 `config_transfer_smoke_test.go`，只用临时假配置和本地假上游。

Seam 放在“输入配置快照和选择，返回迁移文件或变更计划”的位置。调用者和单元测试跨同一 Interface 验证行为；不暴露大量单字段合并函数供前端拼接规则。

### 3.2 HTTP Adapter

`cmd/gateway/config_transfer.go` 负责三个路径的访问防护、严格请求解码、revision、进程内凭证、锁、附件响应及保存／热重载，不负责重复实现迁移规则。

- `main.go` 只增加路径分派及必要状态组装。
- 同一 `configOpMu` 保护完整保存事务及 OAuth 账户删除与配置绑定的既有串行关系。
- 用现有 `config.Save` 和 `applyRuntimeConfig`，不向自己的 HTTP 端点发请求、不绕过已有运行时传播。
- 时钟与进程签名密钥只提供测试所需的内部 Seam；生产使用本机时钟及 `crypto/rand`，不引入外部存储。

### 3.3 页面 Module

`13-config-transfer.js.part` 封装共用弹窗交互。业务冲突、依赖与顺序的权威结果来自服务端；前端只管理选择、请求、预览有效性、确认与下载。

- `00-state.js.part` 只增加初始状态。
- `index.template.html` 增加两页入口和共用弹窗。
- 不修改启停 checkbox 为选择框，不复制 OAuth 账户弹窗业务。
- 不手改构建产物；由现有 webbuild 和固定版本 Tailwind 重建。

## 4. 文件解码与完整性

### 4.1 两类输入

1. 版本化 YAML 迁移包：`kind: ai-gateway.provider-route-transfer`、`version: 1`，仅含 `providers` 与 `routes` 负载。
2. 原生配置：可以是完整 `config.yaml` 或只含上述集合的片段。严格识别已有配置字段，提取两个集合；实际出现的其他顶层配置字段作为“不会导入”的字段名列入预览。

不将 `kind` 或 `version` 写入 `config.Config`，迁移包先由独立封装解析。未知封装类型／版本、未知字段、重复映射键、多个 YAML 文档、无任何提供商／路由条目的文件均拒绝；不加载第三方格式、ZIP 或文件所引用的外部资源。

原生配置全局块只参与严格结构解码，不以其数值替换目标、不应用它们的默认值或取值裁决。最终完整配置校验使用目标全局值。

### 4.2 两阶段校验

**文件阶段，不因未选中而跳过：**

- 所有提供商／路由条目的字段、值类型、配置取值范围、单／多目标互斥、候选数量与重复候选、密钥列表合法性。
- `match` 非空及源文件忽略大小写重复检查。
- 单值／列表密钥和代理密码的保留哨兵检查，发现即拒绝；不从目标回填。
- OAuth 字段组合沿用现有形状校验，但目标账户是否存在留到计划阶段。
- 为迁移片段复用私有校验时，可最小拆分“条目形状”和“目标引用”；普通加载／保存仍执行两者，不更改既有语义。

**计划阶段，只裁决实际新增／覆盖项，并验证最终配置：**

- 合并模式下，路由引用能由目标已有提供商与最终保留／导入的提供商满足。
- 替换模式下，全部引用必须由源提供商集合满足，不能借用将被删除的目标提供商。
- OAuth 目标绑定必须存在；保留的目标提供商不因未使用的源账户缺失而被阻止。
- 完整计划重新执行既有配置校验，确保全局、引用、队列等运行要求不变。

取消勾选不能隐藏非法数值；取消未迁移的 OAuth 项可以排除其目标账户依赖。两者不得混淆。

### 4.3 错误不泄露原值

解析器原始错误可能带出 YAML 标量，现有校验错误也可能包含输入内容，因此新端点不得直接返回或记录 `err.Error()`。

迁移错误分类为固定错误码、中文说明、可安全显示的身份／已知字段路径及行列信息。数值或 URL 错误只说明字段和规则，不回显原值；自定义请求头／请求体只显示所属字段名，不展示键值、片段或明文指纹。模板用文本绑定，不将导入字符串作为 HTML 执行。

## 5. 导出规划

1. 前端要求无未保存修改，展示每次含凭据风险确认。
2. 后端校验非空 loopback 同源 Origin、POST、JSON 和 `If-Match`。
3. 在锁内读取与 revision 对应的已加载配置；复制所需嵌套数据，保持请求结束后只读且无共享修改。
4. 全部模式取全部集合；选择模式以原配置路由下标和提供商名称选取，未知或重复选择拒绝。
5. 路由依赖集合包括单目标、全部多目标候选和路由 `vision.provider`，并入导出提供商。只选提供商不反向找路由。
6. 所选路由内部重复模式阻止导出；不会因为未选的重复规则阻止纯提供商或合法子集导出。
7. 保留全部配置字段、真实凭据、启停及有语义的顺序。Provider map 使用稳定键排序，不声称保留原文件声明顺序；`Name` 等运行时／管理视图字段不写入包。
8. 序列化后复验封装和 1 MiB 限制，再一次性设置附件响应，不生成磁盘临时导出文件。

普通配置 GET、raw YAML、原有预览与复制行为继续脱敏。空单值密钥合法，不读取环境、客户端请求头或其他凭据来源补齐。OAuth 只带源本地账户引用，文件提示账户凭据必须另行迁移。

## 6. 导入计划

### 6.1 选择与冲突

- 未提供选择时默认全部；显式选择须同时表达提供商名称列表和源路由下标列表，可为空但不能都为空。
- Provider 名称精确比较，不自动修剪、改大小写或改名。
- 路由冲突键使用与运行时一致的 `strings.ToLower(match)`；不扩展成 glob 等价判定，不修剪匹配模式。
- 源条目与目标冲突默认 `keep`，可逐项 `overwrite`。整体覆盖 Provider 包括凭据模式、全部列表及顺序，不按密钥 ID 拼接；整体覆盖路由包括候选和覆盖字段。
- 选中但 `keep` 的源项不取代目标，不要求解决未实际使用的源账户绑定。依赖该提供商的导入路由仍会使用目标版本，预览明确提示。
- 没有实际变更时显示“无需应用”，不产生会写配置的有效凭证。

### 6.2 路由位置

已有路由顺序原样保留。单个覆盖项在其唯一目标位置替换；新的路由按源文件相对顺序形成一批，按选项整体放在目标数组前或后，默认后。

启用的前置 `*` 对后续启用新增路由构成明确遮挡时发出警告；不自动更改位置，也不承诺分析所有 glob 覆盖关系。最终预览列出完整顺序及每项来源，使用者可改为前插或取消导入。

目标已有重复模式时：未涉及的重复组保留；本次已选源路由与重复组冲突，返回阻止项，要求先整理目标，不能以“第一条”或“最后一条”猜测。整个替换不需要识别被删除的旧组，只要求源集合无重复。

### 6.3 整体替换

替换必须有非空源提供商与非空源路由，不接受选择、逐项冲突或前后插入选项。取源两个集合及源路由顺序，保留目标所有其他配置字段与 `Path`。

预览列出全部新增／覆盖／删除项和路由最终顺序，应用前再次明确“未包含的提供商和路由会被删除”。有同名项时按源整体取代，无自动保留旧密钥。

### 6.4 OAuth 账户映射

目标已有账户列表使用既有不含令牌的账户管理视图。

- 源 `accountId` 在目标存在时可直接匹配；否则同一非空源引用对应一次手动选择，共用于所有实际导入并引用它的提供商。
- 仅绑定目标已有账户，不按邮箱或套餐猜测，不自动创建、导入或更新账户。
- 映射不改变提供商启停状态，不因绑定顺带启用停用项。
- 实际导入项的绑定未解决时禁止应用，包括停用项；未使用的源绑定不阻止其他合并项。
- 没有源账户引用的未绑定 OAuth 提供商无法按账户 ID 映射；提示先在源完成绑定后再导出，或在合并时排除该项及不能满足依赖的路由，不默默挑选目标账户。
- 应用时重新校验目标账户仍存在，复用现有账户删除与配置事务的锁关系。

## 7. 脱敏预览

预览响应只含：

- 源提供商／路由目录、选择状态、身份及提供商／账户依赖。
- 新增、保留、整体覆盖、删除、未变化的动作与数量。
- 变化的配置字段名；嵌套私有内容统一归入 `extraHeaders` 或 `extraBody` 等父字段。
- API Key 的存在性与密钥条目数量，不包含密钥值、前缀、指纹或代理原文。
- 覆盖／删除提供商会影响的目标路由身份，包含候选及路由视觉引用。
- 最终路由顺序、前后插入选项、遮挡警告、被忽略的全局字段名、阻止项。
- 有效计划的凭证和到期时间，不含完整候选配置。

差异来自规范化后的实际计划，不用前端脱敏哨兵参与真实凭据比较。选择、冲突或映射更改后清空旧凭证并重新请求预览。

## 8. 预览凭证与并发

### 8.1 无明文会话存储的凭证

采用进程内密钥签发的不可篡改凭证，避免为了预览在服务器保存额外明文草稿：

- 每个进程使用 `crypto/rand` 生成独立签名密钥，仅在内存中存在；不写配置或环境。无法生成时新传输端点不可用，不降级成无签名凭证。
- 以标准 HMAC-SHA-256 签名，签名验证使用常量时间比较。凭证是版本化、base64url 编码的元信息，不包含 YAML 或明文配置。
- 绑定基础 revision、源文档字节与规范化选项的带密钥摘要、最终完整配置的带密钥摘要、签发时间、10 分钟到期时间和随机 nonce；两个摘要也使用 HMAC 并以用途前缀分域，不暴露可离线猜测弱凭据的公开哈希。
- 规范化选项必须明确默认值、选择和 map 顺序；摘要输入使用明确编码，不做有歧义的字符串拼接。
- 前端应用时重发当次源文档和同一组选项。后端重建计划并对照凭证，不相信前端预览 JSON。

该摘要只用于操作绑定，不作为凭据指纹展示。关闭弹窗后浏览器释放文件、文本、预览、凭证、选择和对象 URL；服务端请求结束后不保留原文或候选配置。过期凭证不需要明文缓存清理；重启换密钥即失效。

### 8.2 有效性

- 三个端点均带明确 `If-Match`。没有前置版本拒绝，不默认使用“当前最新”。
- 预览后的配置 revision 变化，应用返回冲突并要求重新加载／预览，不自动重做合并。
- 文件、选择、冲突、OAuth 映射、模式或插入位置变化均使内容绑定不同，旧凭证不能使用。
- 成功应用发行新 revision，同一凭证重复使用会冲突，不重复保存。
- 保存失败时不改变 revision 或运行时配置；仍在有效期内的同一操作可重试，不消耗一个有状态的“单次票据”。
- OAuth 账户被删除等依赖变化，即使配置版本没有变，也须在应用时重新裁决；不能因凭证有效而跳过引用检查。

## 9. 保存与运行时事务

应用流程：

1. 校验请求大小、Origin、媒体类型、`If-Match`、凭证格式和签名。
2. 进入既有 `configOpMu`；读取当前配置、revision 和目标账户信息。
3. 裁决凭证到期及 revision，重新严格解析源文档、构造完整计划、复核绑定摘要与全部引用。
4. 保留目标全局配置及 `Path`；完整校验并测量最终序列化字节。
5. 预先生成下一 revision；失败不落盘。
6. `config.Save` 一次保存完整候选配置。失败不逐项发布，也不调用 `applyRuntimeConfig`。
7. 成功后调用既有 `applyRuntimeConfig`，统一传播队列、连接池、熔断、选择器、密钥池等；返回新 revision 和安全动作摘要。

“不部分导入”指单个计划不按条目逐次保存／发布，并沿用已有文件保存与恢复机制；不新增跨进程或跨存储的分布式事务。极端 I/O 导致旧文件恢复失败时必须说明磁盘状态需人工确认，不能谎报全部恢复；运行时仍不得发布失败计划。既有热重载后的缓存清理软错误不被误报为业务配置回滚。

运行状态不从源复制。配置不变的目标状态沿用现有 Reconcile；凭据、连接设置、停用或引用变化触发的状态清理按现有规则，不手工抹掉整个实例的状态。

## 10. 安全与体积

- 新端点要求非空 Origin；scheme／host／port 与请求同源且 Origin hostname 为 loopback，`Sec-Fetch-Site: cross-site` 拒绝，复用已有 Host 校验。
- 不将该检查称为身份认证；无 Origin 的既有 API 或 CLI 转发保持原规则。禁止为方便脚本降低新端点限制。
- 导出是附件响应，`Cache-Control: no-store`、`Pragma: no-cache`、`nosniff`；不引入 CORS 放行。
- 每次导出风险确认；覆盖／替换前提示先手动备份。下载文件权限由浏览器与操作系统决定，不能保证为 0600。
- 文件原文和最终完整配置均限 1 MiB；最终以实际落盘 YAML 的 UTF-8 字节计。导出文件也限 1 MiB，不截断。
- JSON 封装的请求体设置独立、有限的 8 MiB 上限，用于容纳 1 MiB 原文的转义及控制选项；原文上限仍为 1 MiB，不能以外层上限扩大上传大小。
- 严格解析请求和文件，限制单文档；只处理数据，不执行脚本、不自动请求 URL、不从上传内容读取本地文件。
- 不存 `localStorage`／`sessionStorage`／IndexedDB、不写导入历史或自动凭据备份；不打印原文、请求体、选项中的私有内容或完整计划。

## 11. 页面流程

### 11.1 草稿闸门

复用现有 `isDirty()`，同时检查可视配置、YAML 编辑器以及仍打开的提供商／路由编辑表单。点击入口、真正导出及应用前再次检查；只提示先保存或取消，不调用自动保存，也不自动丢弃。弹窗打开期间若配置被本页其他操作修改，失效旧预览。

### 11.2 导出

两页按钮打开同一弹窗，默认全部配置。选择模式列出提供商和路由，可全选／清空；路由自动依赖用独立提示标明，不让使用者误以为它们可以从完整路由包删除。显示条目／密钥数量及 OAuth 外部账户提示，确认风险后请求附件并本地下载，及时 revoke 对象 URL。

### 11.3 导入

上传或粘贴只在当次弹窗内；服务端首轮解析返回无敏感值目录，默认全部、合并、保留冲突、后插。使用者选择条目、逐项处理冲突、映射账户、决定位置，再获取最终预览。

源结构错误返回安全错误，不生成可应用计划。缺依赖、冲突歧义或绑定未解决时，返回可修正阻止项；仍可调整选项重新预览，不因为一次预览失败自动写配置。

显示最终动作、受影响路由和顺序。整体替换独立二次破坏性确认。凭证过期或冲突后禁止沿用确认按钮；应用成功重新读取脱敏配置和账户，清空当次敏感状态。

取消／ESC／关闭只终止未提交操作并清空临时内容，不把已经提交的服务器事务描述成可撤销。请求已发出但响应丢失时，明确结果未确认，重新读取当前配置检查；不自动重复写入或谎报保存失败且完全未改变。

## 12. 测试与验证

### Module 单元测试

- 封装版本、未知字段、重复键、多文档、原生全局提取及无条目输入。
- 完整与片段、单／多目标、候选与密钥顺序、指针 nil／显式 0／false、ExtraBody 类型保留及无源对象修改。
- 真／空单值密钥、停用／冷却密钥的配置与运行状态分离、代理密码、占位符拒绝。
- 导出依赖、纯提供商、重复路由合法子集／全部失败、体积边界。
- 合并 keep／overwrite、前后插、重复目标匹配歧义、源内部重复、替换删项与全局保留。
- 未选项结构错误与不涉及外部依赖的区分、OAuth 共享映射、不按邮箱猜测、停用状态不变。
- 预览只含安全元信息，恶意标量解析错误不得反射敏感字符串。

### HTTP／事务测试

- POST、非空同源 loopback Origin、跨站／非本机／无 Origin、类型、版本前置条件、body 限制与附件头。
- 普通 GET／raw／原有预览脱敏回归，单值／列表／代理凭据和 ExtraHeaders／ExtraBody 不泄露。
- 凭证伪造、篡改文档／选项、时钟过期、进程密钥变化、revision 并发、重复应用及账户删除。
- 预览不写盘、不改变 revision、不触发网络；保存失败、revision 生成失败不发布部分计划。
- 完整应用保留全局、正确 Reconcile，HTTP 响应丢失场景不误报事务状态。

### 浏览器与 smoke

先读全局 Playwright 笔记，使用有状态 API mock 和假凭据；用同一脚本跑基线与改后结果。验证双入口、dirty 拦截、下载字节、选择与依赖、keep／overwrite、顺序、替换确认、OAuth、过期／关闭清理、预览与 DOM 无明文、无上游请求。

再用临时目录中的假配置、本地假上游和隔离端口运行端到端 smoke，记录准确命令；不得 PUT 正式服务的真实配置，不因 smoke 修改本地凭据。

最终在 Docker 中执行 gofmt、全量测试、vet、race 和 `CGO_ENABLED=0` 静态构建。分别重建 HTML／Tailwind，真实执行 `go run ./cmd/webbuild -check` 并确认退出码，再核验样式表。镜像／权限不满足则暂停请使用者处理，不能默默使用过期镜像并称完整验收。

## 13. 不变项与风险提示

- 原有完整配置保存、重载、哨兵保留、OAuth 账户传输与客户端转发规则不被此需求替换。
- 排除全局设置意味着迁移的是接入／路由配置，不保证两个实例的全局 failover、超时或代理环境相同；预览明确目标全局设置保留。
- OAuth 配置包不是账户备份；先迁移账户再映射，实际绑定未解决不可应用。
- YAML 重新序列化保留配置语义，不承诺注释、锚点、排版或 Provider 声明顺序原样往返。
- 明文下载文件由使用者保管，页面无缓存不等于浏览器、下载目录或操作系统能安全擦除；内存清理是释放引用，不声称能保证即时物理清零。
- 新增端点的 Origin 限制不能防御本机恶意进程或同源 XSS，可信本机部署及现有访问控制仍是前提。
