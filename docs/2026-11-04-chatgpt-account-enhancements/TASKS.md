## 当前实现与已有问题

已有能力：OAuth 授权与手动回调、请求时刷新令牌、用量窗口及重置时间查询、授权和可选订阅时间、标签备注、关键词搜索、绑定和换绑、解绑并停用提供商、文件和文本导入、多格式导出。

已核对的限制：

- 普通配置保存仍无条件检查 OAuth 账户引用，停用且未绑定的提供商会阻断整份配置保存。
- 重复导入按上游账户身份跳过，不覆盖已有凭据。
- 账户 `ready` 只描述凭据条件，不证明实际调用成功；OAuth 提供商健康检查当前是本地状态检查。
- 用量缓存保留最近成功快照，但账户筛选没有独立状态、绑定状态和额度排序。
- 提供商并发、熔断和负载策略已有实现，尚无跨提供商共享的账户级准入和额度排序。
- `internal/chatgptauth` 尚无独立 `*_test.go`；网关已有部分假账户转发测试和导入导出浏览器脚本。
- 开发与正式 Compose 有意共享账户文件。进程内互斥锁和原子文件替换不能保证多进程更新安全。

前两类欠账及专项覆盖继续以 [统一已知问题](../KNOWN_ISSUES.md) 为问题来源。本需求承接修复和补测，但在真实验收前不关闭原记录。

### 第一阶段：稳定性与状态语义

- [x] T01 统一普通配置保存的 OAuth 引用校验，允许停用且未绑定的合法提供商 | P0 | 1–2 小时 | 无
- [x] T02 建立账户模块的假时钟、假上游和持久化故障测试入口，补 OAuth 回调、刷新、用量、元数据和旧格式导入导出的基础专项测试 | P0 | 4–8 小时 | 无
- [x] T03 增加授权、用量查询、实际调用及数据新鲜度的独立安全视图，保留旧状态字段兼容 | P0 | 3–5 小时 | T02
- [x] T04 更新账户状态文案和提供商健康提示，明确“可自动刷新”和“尚未实测”，不把本地凭据状态显示为调用健康 | P1 | 2–3 小时 | T03
- [x] T05 验收绑定、解绑、普通保存、重绑、状态时间推进、失败回滚及旧页面兼容 | P0 | 2–4 小时 | T01–T04

设计调整（第一阶段实现中确定，详见 DESIGN.md 2.1 与 API_SPEC.md 2.1）：提供商健康新增 `unverified` 档位；刷新失败与调用结果只在运行期保存；成功响应头之后的中断单列 `stream_interrupted`；刷新轮换后写盘失败保留内存新凭据并标记 `credentialsUnsaved`。

验收要点：

- 解绑后可保存无关设置；启用但未绑定、或引用不存在账户的提供商仍被拒绝。
- 同账户重复绑定保留原提供商启停状态；重绑不丢失路由及其他配置。
- 有刷新凭据的访问令牌到期不直接等同于需要重新授权。
- 用量查询失败保留旧快照并显示数据时间；没有真实调用时显示未知，而非健康。

- [x] T06 提取只读导入计划，逐条报告新增、重复、显式更新、无效条目及身份冲突 | P0 | 3–5 小时 | T02
- [x] T07 实现有版本保护的显式凭据更新，协调刷新锁并保留账户 ID、绑定、标签、备注、暂停状态和首次授权时间 | P0 | 3–5 小时 | T03、T06
- [x] T08 新增导入预检和应用接口，绑定输入、选择、账户版本及有效期，重新校验后原子保存 | P0 | 3–5 小时 | T06、T07
- [x] T09 在现有导入导出弹窗加入预检、逐项选择和更新确认，保持旧导出和文件、文本入口 | P1 | 3–5 小时 | T08
- [x] T10 实现本地检查、刷新链路、用量和可选实际调用的分层诊断，不自动进行消耗额度的请求 | P1 | 3–5 小时 | T03
- [x] T11 增加诊断入口和脱敏结果展示，区分代理来源、授权错误、额度问题、模型问题与查询失败 | P1 | 2–4 小时 | T10
- [x] T12 验收导入更新、过期预检、并发刷新、旧凭据覆盖保护、代理路由和诊断取消 | P0 | 3–5 小时 | T07–T11

设计调整（第二阶段实现中确定，详见 DESIGN.md 3.1、3.2 末尾与 API_SPEC.md 3.3、4.1）：诊断请求用 `refreshMode` 字符串枚举代替布尔 `forceRefresh`；本地检查总会执行；预算耗尽按取消处理，不写入用量或调用失败；刷新锁和用量锁改为可取消等待；实际调用写回账户最近调用记录，但不进请求日志、指标和熔断器。

验收要点：

- 默认重复导入仍跳过；只有身份匹配且明确选择更新时才覆盖凭据。
- 不凭邮箱合并账户，不把解码令牌声明当成已验证所有权。
- 预检不落盘、不刷新令牌、不调用上游；错误和响应无令牌原文。
- 并发刷新不能把新导入凭据覆盖回旧值；失败不得保留半批次变更。
- 实际调用诊断必须有明确账户、提供商和模型选择，并先提示额度消耗。

- 账户恢复不自动启用原本停用的提供商；暂停不清空账户绑定。
- “选择当前筛选结果”不能悄悄包含被隐藏的账户，排序不能改写路由候选顺序。
- 额度未知、缓存过期和重置已到但未复查不显示为满额。
- 批量删除先显示影响，遇到账户被绑定不擅自解绑，也不留下部分删除。

### 第四阶段：账户观测、事件与提醒

- [x] T20 为真实上游尝试记录账户身份快照和调用来源，防止换绑后错误归属 | P1 | 3–5 小时 | T03
- [x] T21 增加有界的账户级窗口统计和本进程累计，区分真实请求、跳过、本地重试、诊断和管理请求 | P1 | 3–5 小时 | T20
- [x] T22 在账户详情展示请求量、成功率、延迟、限流和最后成功时间，标注统计窗口与样本量 | P1 | 2–4 小时 | T21
- [x] T23 扩展现有运行事件流，增加账户维度及授权、刷新、更新、绑定和恢复事件 | P1 | 3–5 小时 | T03、T07、T13、T20
- [x] T24 实现本地状态变化提醒、去重和恢复通知；按确认的渠道扩展外部通知并保护消息内容 | P2 | 3–6 小时 | T23；确认 D02
- [x] T25 验收尝试归属、失败后转移、统计容量、事件去重、恢复证据、通知关闭和脱敏 | P0 | 3–5 小时 | T20–T24

验收要点：

- 同一账户经多个提供商的请求可汇总，但网关请求统计不冒充上游订阅余额。
- 顶层请求日志仍每次客户端请求只记一条；账户真实尝试可以包含本地重试和故障转移。
- 数据不由最近请求日志容量决定；没有样本时不显示虚假的成功率或延迟。
- 时间经过、冷却到期、旧请求迟到成功均不独自证明恢复。
- 外部通知只有明确配置并确认启用后才允许发出。

- [x] T26 细化账户共享策略和可选配置，定义上下界、零值、覆盖关系及热重载语义 | P1 | 2–4 小时 | T13；确认 D03、D04
- [x] T27 实现账户和提供商的联合准入、完整等待预算、取消及幂等释放，避免双层排队占槽 | P1 | 5–8 小时 | T26
- [x] T28 按明确错误范围共享账户冷却，遵守 Retry-After，使用版本和请求序号隔离旧结果 | P1 | 4–6 小时 | T20、T26、T27
- [x] T29 增加显式启用的额度感知排序，保留既有策略、会话粘性和故障转移额度 | P2 | 4–6 小时 | T21、T28；确认 D05
- [x] T30 展示账户准入、共享冷却和候选跳过原因，以及最早可重试时间 | P1 | 2–4 小时 | T27–T29
- [x] T31 验收跨提供商并发、冷却恢复、混合候选、粘性换绑、直通模式和流式提交边界 | P0 | 4–6 小时 | T26–T30

验收要点：

- 同一账户共享资源约束，不因创建更多提供商而获得更多账户额度。
- 未开启新策略时，既有路由顺序和直通模式行为保持兼容。
- 不在持有提供商槽时等待账户槽，或持有账户槽时等待提供商槽。
- 未真实调用的账户跳过不消耗候选尝试额度，也不作为上游熔断失败。
- 额度未知不硬拒绝；多种用量窗口不可不加区分地取最小值。
- 响应提交给客户端后不换账户或候选；任何切换均遵守现有预算与上游限额。

验收要点：

- 共享账户文件场景未具备安全协调前，不能自动开启后台写入。

- 网络故障不直接标记重新授权；有效退避期间不由不同入口重复冲击上游。
- 关闭后台循环可取消等待和出网，热重载不遗留重复 worker。

- [x] T40 增加备份、解密预检和影响确认界面，明确第三方导出与原生备份的区别 | P2 | 3–5 小时 | T38、T39
- [x] T41 验收密码错误、篡改、资源上限、未知版本、重复身份、绑定映射、跨实例恢复和落盘失败 | P0 | 4–6 小时 | T37–T40

验收要点：

- 加密备份保留所选账户的凭据、标签、备注和授权时间；不把瞬态状态当成可恢复健康状态。
- 使用带认证的加密和随机盐、随机 nonce，不自创加密算法。
- 不保存密码，不自动刷新凭据，不在 URL、日志、缓存或预检结果中保留解密原文。
- 保留现有第三方兼容导出语义，不给其文件偷偷加上本地元数据。
- 账户与配置是不同持久化文件，不宣称分别保存就是跨文件原子事务。
