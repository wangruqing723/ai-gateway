# OAuth 模型目录与提供商余额查询

创建日期：2026-11-07。
代码核对基线：`7ceddd7`，`dev` 分支。
状态：T01–T16 已实现并通过本地假数据验收；用户于 2026-11-08 授权提交 dev、快进合并 master 并推送。真实上游站点兼容性未实测。

设计：[DESIGN.md](DESIGN.md)。接口：[API_SPEC.md](API_SPEC.md)。页面使用与手动验收：[USAGE.md](USAGE.md)。

## 已确认需求

- 绑定 ChatGPT OAuth 账户的提供商，在配置路由时支持查询远端模型，不再一律要求手动输入。
- 提供商列表支持查询常用上游的账户余额，首批适配 New API 和用户指定的 Sub2API。
- 允许单独配置余额查询令牌；模型调用密钥和面板账户令牌不能混用。
- 默认手动刷新并显示缓存时间，自动刷新作为显式可选设置。
- 沿用本会话的文档模式，由 Claude 实现。新需求不追加到已提交的账户增强文档中。

## 本轮边界

- 首批仅承诺 New API、Sub2API 与已有的 ChatGPT OAuth 模型目录，不把所有兼容 OpenAI 的中转站自动认作其中一种。
- 账户余额、密钥限额、订阅周期额度分别显示。查不到真正的账户余额时明确说明，不能把密钥无限额解释成账户余额无限。
- 余额查询仅观测，不参与路由排序、熔断、账户冷却、密钥冷却或请求指标，不因余额为零自动停用提供商。
- 不增加充值、扣款、管理员账户读取、自动登录上游、存储上游账号密码或续期上游面板令牌的功能。
- 不改变 Compose、共享账户文件关系、原有模型转发路径或已有第三方导出格式。
- 普通模型提供商继续使用已有模型查询行为。OAuth 分支接入真实远端目录，失败仍可手动填写。
- 实现验证只用假配置、假凭据和本机假上游；不读取 `config.yaml`、`.env` 或真实 OAuth 账户库，不请求真实模型或真实余额。
- 不安装浏览器、字体或新前端资源，不新增未收录的图标名，不升级 Go 语言版本或引入新依赖。

## 已核验现状

- 后端模型查询对 `chatgptOAuth` 返回 `manualOnly: true`；前端也提前返回“没有模型目录”，实际没有出网。
- 普通模型列表由已保存的提供商配置查询，路由抽屉与行内模型编辑共用入口。浏览器当前按提供商名称、URL、格式缓存一天，未把 OAuth 绑定身份纳入缓存。
- 现有配置保存为全量替换，新增字段必须贯穿归一化、表单、保存载荷、原始 YAML、脱敏回填和配置迁移。
- 当前无提供商余额配置、适配器、查询接口或展示；不能复用请求 token 统计冒充余额。

## 推荐方案摘要

以下取值已随用户于 2026-11-07 确认方案冻结。

| 项目 | 推荐方案 |
|---|---|
| OAuth 模型来源 | 官方 Codex 模型目录，使用绑定账户身份；不硬编模型清单 |
| 模型缓存 | OAuth 服务端内存缓存 5 分钟，绑定配置与账户凭据世代；不写浏览器持久化存储 |
| 模型刷新 | 沿用模型组合框，增加明确的“刷新远端模型”；查询失败保留手工输入和已有值 |
| 余额适配选择 | 在提供商编辑中显式选 New API 或 Sub2API，不后台盲探多个站点接口 |
| 查询来源 | `source: auto` 优先独立账户令牌；未配置时用选定 API Key 查询，并按响应标注实际口径 |
| 多密钥提供商 | 余额使用明确选定的一把查询密钥，不自动轮换、不求和；独立账户令牌无需指定调用密钥 |
| 余额刷新 | 默认手动；每提供商可选自动周期，默认 0 表示关闭，开启范围 5–1440 分钟 |
| 缓存与限频 | 内存成功快照 5 分钟视为新鲜；同来源刷新最短间隔 30 秒；失败保留旧快照及旧成功时间 |
| 查询预算 | OAuth 可取消阶段 30 秒、目录 HTTP 10 秒；轮换后安全写回沿用独立存储等待；余额链 15 秒 |
| 余额批量刷新 | 最多 50 个提供商，最多并行 2 个，总预算 60 秒；按查询来源去重，每项独立报告 |
| 查询令牌保护 | 独立脱敏占位符，普通响应不返回明文；仅已有显式敏感配置导出可携带实际令牌 |
| 初期展示 | 提供商列表新增“余额 / 配额”列与逐行刷新，详情展示来源、单位、时间和错误 |

## 关键验收标准

- OAuth 目录按绑定的账户返回，配置路由时可搜索和选择；`supported_in_api: false` 不使 OAuth 模型被误删。
- 查目录不发模型生成请求，不推高真实调用统计，也不把目录成功标记为模型调用健康。
- 换绑、更换查询令牌、密钥、URL、用户 ID 后旧缓存立即失效，旧请求不能把结果写回新身份。
- 独立余额令牌失败必须如实报错，不能悄悄切回调用密钥或展示另一账户的数据。
- New API 的 `quota` / `used_quota` 与密钥限额分开。无法核实换算比时显示原始配额单位，不固定除以 500000。
- Sub2API 的钱包余额、密钥限额、周期订阅和仅用量分别处理；缺失不是 0，`remaining: -1` 只在已核验订阅语义下表示不限额。
- 多密钥查询不轮换、不求和；共享账户的多行余额不能解释成多个独立余额。
- 默认打开提供商列表只读本地缓存，不打上游余额接口；用户明确开启自动刷新后才产生周期查询。
- 超时、取消、鉴权拒绝、404、HTML 登录页、过大响应和无效数值都只输出固定安全错误。
- 所有普通配置、余额、模型、错误、日志、事件和浏览器存储均不泄露新查询令牌或原始上游资料。
- 配置未使用新增字段时保持兼容；普通保存无关配置不丢失新增字段。
