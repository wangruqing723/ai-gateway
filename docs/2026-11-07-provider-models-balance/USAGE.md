# 页面使用与手动验收

本说明对应 `docs/2026-11-07-provider-models-balance/`，功能尚未提交时必须运行本轮工作区构建的后端与页面，不能只更新前端后连接旧后端。

## 使用前

- 本次自动测试只使用假账户、假令牌和本机假上游，没有查询你的真实余额或请求真实模型。
- 管理页面通过 localhost/127.0.0.1 或 SSH 本地端口转发访问，不直接向公网暴露。
- 不在对话、截图或问题报告中粘贴查询令牌。独立账户令牌可能比模型 API Key 权限更大，只授予所需的本人读取权限。
- 开发与正式 Compose 共享配置和账户库。不要让不支持新增字段的旧版本同时改写这些文件；升级前备份，回退前检查新增字段兼容性。
- 本文不要求删除、暂停或替换真实账户来验证。模型选择与余额查询都不执行生成请求，但必要的 OAuth 令牌刷新可能更新凭据。

## 一、配置 OAuth 远端模型

1. 进入“提供商”，确认目标 Provider 使用 ChatGPT OAuth 并已绑定账户，先保存配置。
2. 进入“路由”，打开新增或编辑抽屉，选择该 Provider。
3. 聚焦目标模型输入框或打开模型下拉。网关使用绑定账户查询远端目录，可搜索并用方向键、回车选择。
4. 需要更新目录时点“刷新远端模型”。下拉显示来源、查询时间及缓存/旧目录状态。
5. 路由列表中的行内模型编辑也支持相同目录查询与明确刷新。
6. 查询失败时保留原模型输入，仍能手动填写并保存。目录没有列出某个名字不代表禁止使用它，目录成功也不代表已验证生成调用。

高级兼容项位于 OAuth Provider 编辑区的“模型目录兼容版本”。默认值为 `0.167.0`，普通情况下留空即可。不要把这个字段当作模型版本或转发 UA。

可安全验收：

| 操作 | 应见结果 |
|---|---|
| 打开 OAuth 模型下拉 | 出现远端可见模型或明确错误，不再固定显示“OAuth 不提供目录” |
| 选择或搜索目录模型 | 输入框填入所选名称，其他路由设置不变 |
| 手动输入自定义模型后刷新 | 手填值不被清空或自动覆盖 |
| 关闭下拉或切换编辑对象 | 旧请求结果不写到新对象 |
| 再次打开 | 服务端缓存可复用，查询时间不伪装成刚成功 |
| 上游目录暂时失败 | 若同账户有旧目录，显示旧目录和失败说明；否则保留手填入口 |

目录缓存约 5 分钟。失败后有短暂重试等待，遇上游 Retry-After 则遵守更长等待。取消目录等待不能撤销已发生的 OAuth 令牌轮换。

## 二、配置 New API 余额查询

1. 进入“提供商”，编辑目标 Provider，展开“余额查询”。
2. 适配类型选“New API”。
3. 查询来源按实际凭据选择：
   - “账户（独立令牌）”：查询真实账户配额。填写上游个人/系统访问令牌，不是模型调用 API Key。
   - “选定调用密钥”：查询密钥限额；若上游明确授权返回账户额度，则额外展示账户项。
   - “自动（独立令牌优先）”：有独立令牌就只查账户，没有则走调用密钥。独立令牌被拒不会偷偷回退。
4. 旧版站点要求用户 ID 时填写“旧版 New API 用户 ID”。新版通常不需要该头，个人令牌需具有 `profile:read` 权限。
5. “管理站点基址”通常留空。默认使用 Provider 地址去掉末尾 `/v1`，保留反代子路径。管理面在其他地址时明确填写；只有独立账户令牌允许查询不同 origin。
6. “每 1 USD 的原始配额”通常留空，由站点公开设置发现。只有确认运营站点换算比例时才填写，不要盲填 500000。
7. 自动刷新默认 0，即手动。需要后台刷新时填写 5–1440 分钟。
8. 保存 Provider，再回列表点该行“刷新”。

查看口径：

- “账户余额”代表查询令牌所属账户的钱包/原始配额，不等于某把 API Key 的限额。
- “密钥额度”只属于选定密钥。“不限额（仅此项）”不代表账户有无限余额。
- 显示 `quota` 表示无法确认换算，详情会说明原因。不会把无法确认的数值强行标为美元。
- 详情中保留原始配额和换算来源，便于与上游页面核对。

## 三、配置 Sub2API 余额查询

1. 编辑 Provider，展开“余额查询”，适配类型选择“Sub2API”。
2. 通常选择“自动”并不填独立令牌，使用当前已保存的模型 API Key 查询 `/v1/usage`。
3. 多密钥 Provider 必须明确选择用于查询的一把密钥。查询不切换密钥、不把多把额度相加。
4. 如果 API Key 接口只返回密钥限额，而你需要账户钱包余额，选择“账户（独立令牌）”，填写本人面板 JWT。
5. 保存后在列表刷新，按实际响应显示“账户余额”“密钥额度”“订阅额度（非钱包）”或“仅用量，剩余未知”。

Sub2API 的面板 JWT 可能过期、撤销或绑定 IP/UA。本功能不保存上游密码、不自动登录或续期。凭据被拒时应重新配置合适令牌，而不是关闭上游安全机制。

## 四、列表查看、刷新与凭据维护

- “余额 / 配额”列展示数值与口径，“查询详情”展示来源、成功时间、最近尝试、下次计划、窗口和安全错误。
- “刷新当前列表余额”只刷新当前筛选中已配置余额查询的 Provider。超过 50 项会要求缩小筛选，不静默截断。
- 同一来源的连续刷新受到约 30 秒最短间隔限制。受上游限流时等待更长时间，不代表余额到时自动恢复。
- 查询失败时保留上一次成功数值及其时间，并显示失败/旧数据。缺失值是未知，不是 0。
- 显式开启自动刷新后由服务端调度，不要求页面一直开着。停用 Provider 不自动刷新，手动仍可查询。
- 默认打开列表只读取本地缓存，不向全部上游发余额请求。页面周期读取缓存不等于自动出网刷新。
- 显示共享来源的 Provider 不能把余额相加。列表密钥的冷却按 Provider 隔离，不跨 Provider 借用其他密钥状态。
- 编辑已有查询令牌时留空表示保留；需要删除时勾选“明确清除已保存查询令牌”。账户模式清除后需改来源或关闭查询才能保存。
- 更改适配类型、查询目标或 Provider 名称后，必须重新填写独立令牌，不能把保留占位符发送到新目标。
- 提供商/路由的显式敏感配置导出包含查询令牌，下载文件须妥善保管。普通配置查看与 YAML 预览只显示占位符。

## 五、手动验收清单

优先从无副作用的页面检查开始，再针对你明确配置的站点执行手动查询：

1. 不启用自动刷新，打开列表，确认显示“尚未查询”而不是伪造零余额。
2. 配置一项余额查询并保存，刷新该行，与上游页面核对口径和单位。
3. 再次快速点击，确认使用缓存/限频，不不断请求上游。
4. 修改不相关字段后保存并重新打开，确认余额配置保留，令牌仅显示“已配置”。
5. 关闭令牌表单再重新打开，输入框为空，不回显真实令牌。
6. 在路由抽屉与行内编辑分别查询 OAuth 模型，确认刷新不覆盖手填名称。
7. 在窄窗口检查余额设置的滚动、按钮、密码框和查询详情，确保可用键盘到达。

鉴权失败、不同身份、并发取消、限流、超大响应和无效 JSON 已用假上游测试，不建议用真实账户反复制造这些故障。
