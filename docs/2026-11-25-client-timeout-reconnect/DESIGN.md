# 客户端控制超时与持续重试设计

## 1. 配置契约

以下命名为本次规划提案，随任务摘要一起确认：

- Route/Target 新增 `timeoutMode`：省略表示继承；`global` 表示显式采用现有全局超时；`client` 表示取消网关生成时限。候选优先于路由，最终默认 global。Provider 不增加此字段。
- Route/Target 的 `localRetry` 增加 `mode`：省略表示继承，`limited` 为默认有限重试，`untilDisconnect` 为持续重试。候选可用 limited 覆盖路由持续模式。Provider 既有 maxRetries/intervalMs 保留，不增加可配置持续模式；若共享结构承载 mode，Provider 填该项应明确拒绝而非静默忽略。
- `maxRetries` 与 `intervalMs` 继续逐字段按 target > route > provider 解析；持续模式忽略 maxRetries但保留配置，切回limited恢复其原值，0仍为有限模式关闭值。
- 持续模式的最终有效 intervalMs 必须大于0；仍使用现有1000ms默认值及60000ms上限。校验有效覆盖组合，不能拒绝被候选合法覆盖掉的路由值。
- timeoutMode与重试mode正交：取消超时不自动启用重试，持续重试也不自动取消单次超时。

## 2. 超时实现要求

`forwardAttemptTimeouts`、`requestChainBudgetMs`、proxy非流式WithTimeout和流式头部/活跃timer均需核对。不能简单传0：部分路径可能将0补默认或创建立即到期的context。

给proxy显式的关闭生成时限状态，仅对已解析为client的候选生效。客户端请求context始终保留。HTTP transport的拨号/TLS保护、排队maxQueueWait、独立vision预算保持不变；不得为单次请求修改共享http.Client或Transport。

client模式的密钥切换不再被全局生成超时派生预算挡住，仍只在提交前切换，遵守冷却与候选选择。预读最长3秒是提交策略而非请求失败超时，保持不变；预读已提交响应后不可重试。

流式转非流式、上游错误正文读取、响应写入deadline都需明确区分生成等待和基础传输保护，防止只改入口而下层仍回落全局生成时限。代理或客户端自身超时仍可能先结束连接，网关不保证无限存活。

## 3. 持续重试状态机

只有响应尚未提交、客户端context未取消、失败可恢复时才重新发请求。沿用既有失败分类作为基础，但持续模式不得因普通4xx/鉴权开关默认允许转移就永久循环不可修复的400/401/403。连接类错误、可恢复5xx/429可进入持续重试；请求构建/格式转换错误立即结束。

每次尝试单独Acquire/release，固定间隔和冷却等待期间不持队列槽。客户端断开同时中止网络请求、重试间隔、冷却等待，不切换候选。

密钥/账户冷却仍由既有状态机维护；有恢复时间时按不早于恢复时间与重试间隔的约束等待，再重新选密钥，不永久保留旧排除集合。全部密钥停用、Provider停用、账户暂停等没有自动恢复时间的人工状态不无限等待。不得在等待中调用成功上报或清空冷却。熔断准入仍保留，已进入的候选最终只上报一次，任何退出都归还探针额度。

持续模式不因长Retry-After走现有freeAttempt直接转移到下一候选，应等待可恢复时点；有限模式保持原行为。持续模式启用并进入候选后不能自动转向后续候选；不可恢复错误返回该候选终态。

注意：client模式上游一直沉默但连接未报错时，会一直等待客户端断开，不主动重连。这是用户已确认的取舍，UI需明确说明。

## 4. 前端与调试兼容

路由和候选各提供超时模式（继承/全局/客户端）与重试模式（继承/有限/持续）。显示有效来源和提示：持续重试可能一直不轮到后续候选；响应输出后不自动重放；客户端模式单次沉默连接不自动超时重试。

把新字段串接到normalize、表单初值、编辑、复制、保存、YAML、导入导出和候选重建全部路径。仅隐藏持续模式下的次数输入，不在保存时擅自清空旧次数。

调试route/target模式沿用已保存配置，包括新超时/重试策略；中止按钮必须取消上游。Provider隔离单发仍保持隔离语义，不自动套用路由持续策略。

## 5. 验证与实施顺序

当前调试控制台C组完成后实施，避免同文件并发写入。本需求后端、测试、UI分批交Codex，每批由Claude实跑评审。测试用短时假上游与可取消context，不依赖真实provider、真实凭据或长时间sleep；需要证明既有全局超时已过但client模式仍可成功，客户端中止仍及时释放资源。

必测：target显式global/limited覆盖route；client下stream/non-stream和直通/队列；持续模式超过有限次数仍可成功；400/无凭据不无限循环；429及账户冷却等待后恢复；取消等待无后续请求；提交部分内容后失败不重放；普通有限重试与全局超时旧测试不变。

## 已确认行为补充（2026-11-26）

- UI 的 Route / Target 都提供超时模式与本地重试模式选择，并显示当前有效模式及其继承来源。Route 省略 `timeoutMode` 时采用全局超时；Target 可显式设 `global` 覆盖 Route 的 `client`。Provider 表单不提供 mode 或 `timeoutMode`。
- `untilDisconnect` 下隐藏有限次数输入但保留原 `maxRetries`，切回 `limited` 后恢复。重试次数和间隔仍按 target > route > provider 逐字段覆盖；持续模式的间隔校验针对每个候选最终有效值，必须大于 0 且不超过 60000ms。候选正间隔可以覆盖 Route 的显式 0。
- UI 明确说明 `client` 关闭非流式整体超时、流式响应头等待与活跃生成超时；排队、底层建连/TLS 与独立 vision 超时仍生效。客户端断开终止请求；连接持续沉默但未报错时不会主动重连。
- UI 明确说明持续模式只处理响应提交前可恢复的失败，留在当前候选、不自动轮到后续候选，遵守冷却与固定间隔，响应输出后不自动重放。两种模式彼此独立。
- Route / Target 调试读取最近加载的已保存配置并沿用新模式；Provider 隔离单发保持不变。配置加载、编辑、复制、保存、YAML 预览和配置传输都保留这些字段。
